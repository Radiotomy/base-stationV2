# Pinned versions for the siren-song (HeartMuLa) Cog image.
#
# heartlib is installed HERE, not via `pip install -e .` in cog.yaml's build.run:
# Cog does not make the project source available to build.run commands, and a
# local directory is not an accepted requirements entry either — only remote
# direct references and local wheels/archives are. So we install from git and
# pin the commit, which also makes the image reproducible.
# Swap this for your own fork (and append @<commit> to pin it) if you build from
# a fork rather than upstream. Unpinned = whatever main holds at build time.
git+https://github.com/Radiotomy/heartlib

# ALTERNATIVE — install the checkout you are building from, without git:
#   python -m build --sdist   (writes dist/heartlib-<ver>.tar.gz)
# then replace the line above with:
#   ./dist/heartlib-0.1.0.tar.gz
# Cog accepts a local sdist/wheel path in requirements.txt; it does NOT accept a
# bare local directory, which is why `-e .` is not an option here.

# NOTHING ELSE IS PINNED HERE ON PURPOSE.
#
# heartlib declares its own torch / transformers / tokenizers / numpy versions in
# pyproject.toml, and a second opinion in this file can only contradict it. That
# is exactly what broke the build: we pinned transformers==4.44.2 (which requires
# tokenizers <0.20) while heartlib requires tokenizers==0.22.1 — ResolutionImpossible.
#
# The model's dependency graph belongs to the model. Add a pin below ONLY for a
# package heartlib does not declare at all, and never for one it does.
